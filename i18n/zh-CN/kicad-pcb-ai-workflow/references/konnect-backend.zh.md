# Konnect MCP 后端：连接、操作与验证契约

## 区分四种请求

1. **MCP 在线吗？** 使用协议 ping 或一次已暴露的轻量读取；成功即停止。
2. **KiCad 活动板已连接吗？** 可用时，用预期的板卡路径调用 `open_project`。确认
   IPC、已打开板卡的身份与实际路径。不要为了回答连接问题而创建项目。
3. **有哪些工具可用？** 动态发现当前工具集与相关 MCP schema，除非明确要审计后端，
   否则避免全量工具转储。
4. **该工具可以编辑板卡吗？** 检查本地构建/schema/版本与操作范围的夹具验收。发现
   不等于授权；高风险写入需要受保护的候选板与独立验证。

## 安装与身份

Konnect-EDA 是外部安装的第三方可执行程序，有其自身条款与特定版本行为；它**不打包在
公开 Skill ZIP 中**。历史本地档案记录了 Windows/KiCad 10.0.8 上的商业版 0.14.1，以及
在不同基础上的较旧开源版 0.13.0。这些小规模夹具结果不是普适的运行保证。每当相关
环境变化时，都要核实安装包来源、实际可执行文件 SHA-256、服务器构建、连接身份、
KiCad 版本与目标 PCB。不允许静默降级到不同的后端，也不允许存在隐藏的第二写入者。

## 板卡操作循环

- 创建或选择确切获授权的工作候选板。保护板框、锁定项、位号/封装身份、网表、已获
  认可的布线与规则。
- AI 生成限定范围的计划；Python 检查确定性约束与相关器件卡片。复杂的原理图到 PCB
  同步优先使用 `dry_run`，并把返回的计划修订版绑定到对应的实际调用。
- 使用已验证的、面向具体任务的 Konnect 工具应用有界操作。返回 UUID/网络/几何对象
  身份与实际变更值。超时或响应不确定时，先**读取实际状态**再重试；不要盲目重放
  相对变换。
- 保存当前 KiCad 源文件，释放写入者所有权，用 KiCad CLI 重载独立的原生文件，评估
  ERC/DRC 并核对项目/板卡哈希。AI 与硬件工程师分别评估工程正确性与当前证据。
- 在报告文件夹中保留原始操作回执；模型起初只能看到状态、受影响对象数量、变更的
  UUID 与证据路径，出现问题时再展开。

## 特殊情况

- 基于文件的原理图工具可能与未保存的原理图编辑器状态冲突。编辑前确认编辑器已保存
  当前源文件，并在事后检查导出的原生网表。
- `update_pcb_from_schematic` 是有状态操作：先运行 dry-run，检查创建/更新/移除/锁定
  的对象，并应用确切记录的计划修订版。在原生重新导出与审计之前，成功返回并不能
  证明一致性。
- 移动封装可能使旧走线脱开、改变阻抗、短路受保护对象或违反几何约束。回读实际焊盘，
  并重跑相关 DRC 与 G3/G4。
- Freerouting DSN/SES 交换不等于 KiCad 中已验证的铜皮。确认 SES 导入、实际板卡状态、
  制造规则与已保存的 DRC。
- 如果后端缺少该操作，只用具体的 `BLOCKED` 原因让依赖任务失败；绝不虚构工具名，
  也不把更高的版本号当作自动兼容证明。
