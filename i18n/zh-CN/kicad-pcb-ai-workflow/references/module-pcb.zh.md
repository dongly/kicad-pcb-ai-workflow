# PCB 叠层、放置、布线与铺铜

涉及最终的丝印/阻焊冲突或原理图字段不匹配时，阅读 [已放置字段的修复](pcb-silkscreen-fields.md)。参考文字空间要与元件本体分开预留；刷新库不会重新摆放实例字段。缺失 MCP 字段能力时必须上报，而不是绕过。

1. **放置之前先定叠层与规则：** 获取当前工厂能力、基材/材料与铜厚参数；定义走线/间距、过孔钻孔/直径、孔环、板边间距、差分阻抗、NetClass、电压隔离与板框。通过已验收的 EDA 后端写入并回读生效的 KiCad 规则；仅有一份 JSON 策略并不能证明某条规则已激活。
2. **G3 放置：** 先约束板级机械件、连接器、安装孔、天线与禁布区，再处理电源环路、晶振/去耦、敏感模拟与高速分组，最后做普通放置。使用阶段专属的节点 03 知识卡片。`placement_review.py` 是只读评估器，不是自动布线器或自动放置器。核实实际焊盘几何、UUID、回流路径与布线通道。
3. **分七步布线：** 检查规则，对*每一条*网络分类，规划关键网络，分批执行普通信号，处理电源/地，然后**先填充真实的 GND 铜区**，检查孤岛/焊盘到平面以及跨层回流拓扑，只添加**必需且已批准**的 GND 缝合过孔，**重新填充所有被修改的 GND 铜区并保存/重新加载**，运行 `pcb.ground_plane_audit` 关卡，之后才运行完整的原生 KiCad DRC。填充前出现 GND 飞线是预期现象，不是 G4 失败。参见 [强制的 GND/DRC 顺序](gnd-before-drc.md)。未知网络不得被静默当作普通信号。离线 A* 搜索只是布线提案，不是已施加的铜线；Freerouting 的输出也不能证明 KiCad 导入成功。绝不要以为仅靠最终铜区填充就能满足所有接地连接。
4. **G4：** 检查实际铜层、走线与过孔几何、参考平面、回流环路、RF/天线间距、差分偏斜与制造约束。复用已验证的知识卡片，但不得跳过项目专属证据或工程师批准。

Konnect MCP 是唯一的活跃写入者；Python 只用于算法/校验。如果某个必要操作缺少兼容的已验收工具，应阻断该操作，而不是降低工程规则或暗中改用遗留的 `pcbnew` 写入。参见 [工程规则](engineering-rules.md)、[布线策略](constraint-routing.md)、[放置质量](placement-quality.md) 与 [最新工作流](latest-complete-workflow.md)。

## 规则优先的功能模块布局规划（R10 预览）

在已核准的叠层/板厂规则应用到已同步的 KiCad PCB 之后、任何自动化 G3 移动之前，运行 `pcb.layout_preflight`。它复用现有的 `design_intent_audit.py` 原生生效 NetClass 检查并核实实际的 Board Setup 最小值；随后 `pcb.layout_plan` 在保留当前连接器/机械锚点的前提下，计算有界的模块内位置与小幅的整板模块平移。参见 [规则优先的 PCB 模块布局](pcb-module-layout.md)。这些任务绝不直接编辑 EDA：只通过 Konnect 施加，然后运行保存后的封装位置回读以及既有的**仅放置** G3 关卡（`pcb.placement_pre`，`--phase pre_route`）。**G3 不做整板 KiCad DRC，也没有零未连接要求**；完整 DRC 属于 G4，在布线、电源/GND 处理与铜区重新填充之后进行。不得为了让候选方案成立而降低铜、过孔或 courtyard 规则。


## JLCPCB 2/4/6/8 层工厂约束：G3 之前需用户明确同意

在 G2/F8 之后，运行 `pcb.fab_preview` 提出一份带来源日期的**保守** JLCPCB 刚性 FR-4 档案。列出板层数、标称厚度、成品铜厚、最小线宽/线距、过孔钻孔/直径、孔环、孔到孔间距、板边与 courtyard 间距，以及尚未确定的精确阻抗叠层/表面处理。公布的工厂最小值**不是**本 Skill 的设计默认值。**停下来，取得实际用户的明确确认**；不要自动确认。只有在那之后，`pcb.fab_confirm --apply` 才会创建不可变的审批与板厂规则伴随文件，且不编辑 KiCad。通过获得授权的 Konnect 写入者落实实际的 KiCad Board Setup/NetClass，回读生效的物理规则/叠层，并使用审批中的 `fab_approval` 与 `fab_rules` 运行 `pcb.layout_preflight` → `pcb.layout_plan`。来源、层数、档案或厚度发生漂移时需要用户重新审查。参见 [JLCPCB 确认](jlcpcb-fab-confirmation.md)。

## Courtyard 不是铜间距（R10）

为 G3 候选放置评估时，读取真实的 F.CrtYd/B.CrtYd 机械占位以及当前生效的 KiCad 自定义 `courtyard_clearance` 规则。受支持的、来源绑定的顶部 Courtyard 多边形、显式封装 Keepout 区域、NPTH 安装孔与固定锚点都会在接纳候选之前被筛查。**不得**用封装中心矩形或全局铜间距替代真实 Courtyard。来源声明的焊盘级邻近与去耦关系必须参与放置，而不是只做事后布局审查。未知硬几何将导致阻断。这不是完整的原生 DRC 评估器；在已验收的 Konnect 移动之后，仍要保留保存位置回读，并运行**仅放置**的 G3 审查。原生整板 DRC **只能在 G4 的布线与铜区重新填充之后运行**。参见 [Courtyard 优先的细节](pcb-courtyard-hard-rules.md)。

## 细间距焊盘引出与电源主干

应用用户提供的图表，且 **0.254 mm 仅用于必需的电源主干线宽**，而不是作为每个焊盘引出短铜线的无条件最小值。只有在确有必要时才使用有出处、精确到网络/焊盘/层/区域、长度有界的 neckdown（线宽收窄），且必须高于板厂绝对最小值；核实其**自身**的载流/热/压降预算与局部 KiCad 自定义规则的作用范围。通用网格 A* **尚未**支持变宽线段的布线，也不会自动套用这些例外。没有已验收的 Konnect 操作与回读证据，不得声称具备自动控制能力。参见 [电源 neckdown 契约](constraint-routing.md)。

## 普通网络的 Freerouting 优先候选（不晋升为生产用途）

参见 [分阶段的 Freerouting 优先集成契约](freerouting-primary-routing.md)。在完成整网分类与原生规则/回读检查之后，对普通网络优先采用**合格的对外 DSN/SES Freerouting 候选**，而不是自定义的、由 LLM 操作的全局 A*。使用独立审计的实际 KiCad 成员关系与 `-inc` 保护专用的 GND、RF、差分、大电流与时序关键 NetClass。保持 Konnect 作为唯一的 KiCad 写入者，负责外部候选的导入/保存/回读以及关键的原生编辑。然后重新填充 GND 铜区并运行独立的完整 G4 DRC。当前的外部候选**不是**通用的已验收默认路径：实机整板规则保真度与集成证据仍未补齐。绝不能把 Freerouting 的输出单独当作已布线的制造铜线。

## 必需的七阶段 Freerouting 路径

[Freerouting 七阶段布线](freerouting-seven-stage.md)中的七阶段流程取代了普通网络一律优先 Konnect/全局 A* 的做法：先核实完整清单与工厂/原生规则；放置/锁定特殊的电源、时序、差分与 RF 走线；对剩余的**仅普通**连接使用已批准的 Freerouting 2.5.0（排除 GND 与受保护的 NetClass）；对照受保护的检查点审计导入的 SES；在有界的新检查点上修复；最后重新填充 GND 并运行完整的原生 G4 DRC。在另行测试之前，这并不认证自动化原生导入、保存、KiCad GUI 或生产验收。G3 仍仅做放置。
