# 历史实验性 KiCad IPC 编辑桥（已禁用活跃写入）

**重要：** 自研的 IPC `kicad_bridge` 插件/启动/服务/请求写入路径在 R10 中已禁用。本参考资料仍是一份英文的历史/诊断规格说明，不是启用第二个活跃 EDA 写入者的操作指引。当前的活跃编辑必须使用已验收的 [Konnect 单一写入者工作流](konnect-capability-migration.md)。

## 历史原型契约

实验性桥接使用了 IPC 插件、私有会话目录与预配置的 KiCad Python 客户端，用于受限的 KiCad 10.0.8 板级编辑演示。其原始安装流程可能包括放置在 KiCad IPC 插件位置下的插件、一个连接动作以及 `connection.json` 会话标识，GUI 与 IPC 状态彼此独立。**默认不安装、不调用。** 过期的连接文件并不是板子处于连接状态的证据。

昔日的操作序列是：检查真实的源板与 UUID/焊盘坐标；用 `candidate-manifest.json` 与来源 SHA 准备新的候选；把候选作为独立的板子/会话打开；预览请求的有界封装移动/旋转；只应用一次；读取实际封装/焊盘位置；若被取消或存在歧义，在不盲目重放的前提下进行对账；保存已验收的候选；对保存后的文件独立运行 CLI DRC。

原型使用带 OS 级锁定的私有按用户会话目录。这种锁并不能排除 GUI 手工操作、不同的会话根目录或独立的第三方写入者。前后哈希与回读不构成原子事务保证。对已提交操作的补偿性恢复是一次新操作，而不是宣称过去的提交从未存在；不得覆盖其他编辑器造成的状态变更。

当 Konnect 失败时，不得把遗留插件与桥接写入者选作自动回退。在明确支持的场合仍可使用只读诊断。未来若要实验性复用，需要独立验收的运行时、真实的 GUI 故障注入测试、保存板检查、恢复状态验证，以及与所有活跃项目写入的显式隔离。

参考：[KiCad IPC API](https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/for-addon-developers/)。确切的客户端/API 版本必须在目标 KiCad 安装上独立验证。
