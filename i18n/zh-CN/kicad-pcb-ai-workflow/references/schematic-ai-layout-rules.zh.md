# 拓扑驱动的原理图绘制与可验证的页面几何

**范围：** KiCad 原理图生成、重排、层次化图纸与视觉审查。这是一份工程设计规范与验收规范，**不是**声称当前 Skill 已实现通用的几何原理图求解器。请与 [原理图风格](schematic-style.md)、[系统集成](system-integration.md) 和 [工程规则](engineering-rules.md) 一并适用。

## 0. 设计目标、必备输入与禁止的捷径

读者必须能够从二维图纸还原**真实的电气拓扑、器件角色与设计意图**。优化顺序为**拓扑优先，相对布局其次，绝对坐标最后**。绝不从页面中心推导引脚引出方向，也不得把其他项目的坐标、图幅尺寸或电源页布局当作假定模板复用。

绘制前必须取得：已批准的产品需求与系统/接口契约；确切的器件 MPN、封装、数据手册与勘误表；实际的 KiCad 符号定义（含 unit 划分、隐藏引脚、旋转与镜像）；**独立编写的期望组件/引脚/网络图**；电源域与安全约束；以及项目图纸/文本约定。缺少关键事实即视为 **BLOCKED**。不得用生成的图像或网表去虚构用于核对该图的期望电气图。

## 1. L0–L5 优先级与处置

| 层级 | 对象 | 必须执行的解读 |
|---|---|---|
| **L0 电气事实** | 引脚编号、MPN/取值、引脚-网络关系、串/并联拓扑、供电域、极性、NC/DNP、厂商条件 | 硬性阻断；任何美观理由都不能为修改连接开脱 |
| **L1 几何不变量** | 真实引脚连接点、变换后的引出向量、穿过符号本体的导线、标签锚点、碰撞、图纸区域 | 经确认的硬性违例即阻断；无支撑的自动检测必须提供明确的审查路径 |
| **L2 电路角色** | 主串联路径、并联保护/偏置/去耦支路、反馈、总线/差分信号、连接器、功能块 | 表达真实功能，例外须记录原因 |
| **L3 页面原型** | 变换/电源、MCU/SoC、连接器、存储总线、模拟/音频、分立 I/O、架构总览 | 对页面分类并选择局部构图规则 |
| **L4 软目标** | 可读的走线路径、交叉、折弯、标签、分组、留白、对齐与密度 | 仅在 L0–L3 之后优化，绝不凌驾于硬约束之上 |
| **L5 证据与验收** | 独立的期望网表与原生网表比对、ERC、几何筛查、整页与局部视图、工程师审查 | 如实报告 **AUTO**、**REVIEW** 或 **UNAVAILABLE** |

冲突需求的优先级：**适用法律/安全标准 > 厂商数据手册与勘误表 > 已批准的产品/工程需求 > 独立建立的拓扑 > 页面约束 > 外观**。对无法解决的冲突，停止并取得工程决策；已批准的电路变更需要重新批准期望图。

## 2. 把拓扑转换为可读的页面

1. 按功能、供电域、接口、复用与层次构建功能块图。识别每个功能块的输入、输出、电源、地/参考以及跨边界端口。
2. 从真实的组件-引脚-网络连接中区分串联路径、并联保护/偏置/去耦、反馈环路、差分对、总线、分支与边界。**视觉上的对齐不能证明电气串/并联拓扑。**
3. 读取符号实际的 unit、中心、旋转/镜像，以及库中每个引脚的局部位置、连接点、朝向与长度。把坐标与外向向量变换到页面。绝不能根据引脚出现在页面哪一侧来推断引出方向。
4. 先解出功能块的相对顺序与符号锚点，再把坐标量化到原理图栅格。多个功能电路共用一张图纸时，用直线图形分隔线和/或矩形框进行视觉分组与分隔；这些是图形对象而非电气导线，不得穿过符号、导线、标签或文本。预留导线/文本走廊；在跨块连接之前优先布置反馈与保护支路。
5. **先画导线。** 在每个简单电路及自包含单元电路（一个 IC 及其去耦、一个分压器、一个滤波器、一个带保护的驱动器）内部，优先用真实导线直接连接引脚；标签不能替代短距离连接。只有在 5b 条允许之处才使用标签。
5b. 局部使用短直连线。对于离开功能块、跨越图纸边界或高扇出/长距离的连接，按以下优先顺序使用命名标签：**局部标签（仅限同一张图）→ 层次标签 + 图纸引脚（任何跨图信号）→ 全局标签（仅限有正当理由的全板网络）**。不要为了减少标签数量而画半页长的导线，也不要为了省去构建层次结构而滥用全局标签：全局标签在每张图上都可见，掩盖了接口属于哪个功能块，并使后续对子图的拆分或复用变得不安全。
   **网络标签绝不能直接附着在普通元件引脚或父图中的图纸符号引脚上。** 先从引脚引出一段导线，再把标签锚点放在导线内部——不能在引脚上或导线端点处——并让整段文字覆盖在导线上；名称较长时加长导线。Konnect `connect_to_net`/`batch_connect_to_net` 默认把标签放在引脚端点上，因此要传入能让锚点两侧都留有导线的 `stub_length`，或自行绘制导线。
6. 独立放置位号/值文本、引脚名/编号、标签与注释。检查渲染后的包围盒。任何最终的页面平移都应以**所有相关可见对象的组合包围盒**为准，并从可用页面区域中排除标题栏/边框/预留区域。
7. 同时验证电气与视觉两条通道。对失败项在局部重新布线/重定位；绝不能为了通过报告而删除必需组件、擅自声明 NC、隐藏必要文本或篡改引脚网络。

## 3. L1 精确几何定义

- **原生连接点：** 只有真实的引脚连接点或其他合法的 KiCad 电气节点才算数。落在绘制出的引脚线上的任意接触点并不自动构成连接。要用原生导出的网表区分真正的结点连接与不相连的交叉。
- **引脚引出：** 对离开引脚连接点的第一段非零导线，将其方向与**经过变换的库定义引脚外向向量**比较，考虑旋转与镜像。对非轴向符号、复合节点与电源符号，采用经过验证的几何或明确的审查处理。「引脚在左边」不是有效的方向判定算法。
- **导线穿过符号：** 导线不得穿过其他符号的实际本体或禁止区域。矩形包围盒只是保守的粗筛；经实际几何审查后，可放行贴边或非矩形的合法情况。导线在引脚附近接触包围盒并不会自动使穿过本体的行为合法化。
- **标签连接：** 标签附着锚点必须位于导线或总线的内部（绝不在导线端点，绝不在裸引脚上），并且要有原生网表证据。网络标签文字必须落在其所命名导线的范围之内。层次/全局标签在其锚点处连接，因此导线可以在锚点处结束；其文字向远离引脚一侧延伸。水平 0°/180° 与垂直 90°/270° **仅作为初筛**；要核实实际的 KiCad 标签类型、镜像、变换与渲染文字朝向。不要仅凭角度作为依据。
- **文本碰撞：** KiCad ERC 不检查文本或图形重叠；ERC 通过与否与此无关。要运行 `schematic_overlap.py`（见[构图门禁](schematic-composition-gates.md)），并使用实际的可见文本几何，包括字体、字号、角度与字段可见性。筛查与本体、导线、标签及其他文本的非法重叠。隐藏字段与合法注释遵循明确的例外规则；按字符数估算不能授予 PASS。
- **页面边界：** 功能对象必须保持在可用画布之内，位于标题栏、边框与预留注释区之外。页面边框/标题元素本身不计入对象违例。
- **拓扑与外观：** 串并联关系是 **L0 网表谓词**；共线性是 **L2 可读性默认**。并联的 TVS/去耦电容不得画成串联主路元件，反之亦然。
- **长导线触发：** 块内路径长度超出可用块宽、折弯超过 **两处**，或穿过另一功能块，即触发 **REVIEW/重新布局**。跨块连接优先使用边界标签/端口。相对长度是启发式判断，不是电气验收门槛。
- **共线串联路径：** 在符号几何允许的前提下，优先让元件位于其真实连接节点之间、沿主电流方向排布。**中心偏移 ≤1 格**可作为可配置的软目标，而非普遍的电气要求。
- **并联支路：** TVS、去耦与上/下拉元件通常构成通往正确电源轨/参考的短正交支路。实际拓扑决定朝向；「电源朝上、地朝下」并非僵化规则。
- **视觉中心/密度：** 总包围盒包括符号、导线、结点、标签、可见的位号/值、注释与层次结构。排除边框/标题/预留区域。偏移在**可用跨度的 5%** 以内属于软性建议；允许有意留白。按真实的可读性与项目要求选择 A3/A4 或其他图幅，而不是固定模板。

## 4. L2 按电路角色的语义布局

| 角色 | 默认视觉表达 | 验证内容 |
|---|---|---|
| 串联电阻、磁珠或保险丝 | 主路径上短且对齐的进/出 | 确为串联；无意外旁路 |
| 旁路/去耦 | 从电源轨到参考的短支路 | 供电域、数量、取值与器件指引正确 |
| TVS/钳位/滤波 | 从被保护节点到参考的并联支路 | 极性、电压、接地与放置场景 |
| 上拉/下拉 | 节点 → 电阻 → 正确的参考电源轨 | 上电电平、使能/启动行为 |
| 反馈/补偿 | 靠近控制器件的局部环路 | 采样节点、环路极性与完整网络 |
| 差分对 | 相邻、对齐、P/N 命名无歧义 | 实际引脚/网络极性；绘图对称 **不等于** PCB 等长 |
| 共享引脚/网络 | 确实允许时才做局部合并 | 绝不能因为功能名相同就短接隔离引脚 |
| 多引脚连接器 | 功能面朝内；短而带标签的扇出 | Pin 1、外壳/屏蔽、NC 与完整引脚映射 |

## 5. L3 各页面原型

- **电源变换：** 输入 → 保护 → 变换 → 储能/滤波 → 输出；反馈/使能放在控制器附近。
- **MCU/SoC：** 按实际引脚功能与模块分组；使用合理的跨模块层次。不得为改善外观而改动物理引脚编号或厂商符号语义。
- **USB/多引脚接口：** 连接器短扇出；CC/VBUS/ESD 按实际连接放置；清晰区分差分极性。
- **SD/存储/总线：** 控制器 → 可选的串联/匹配 → 连接器或目标器件；上拉是实际支路，标签不得掩盖方向。
- **模拟/音频：** 输入 → 调理 → 输出；反馈与去耦保持局部；区分模拟/数字电源与参考。
- **调试/端口扩展：** 短而带标签的分支、分组网络、可见的参考；避免人为的串联链表现。
- **用户 I/O：** 按键、LED、蜂鸣器、执行器等按独立功能分组。
- **层次总览：** 展示真实流向、模块、供电域与明确约束的接口；而非仅作装饰的方块。

**先层次结构，后全局标签。** 只要存在不止一个功能模块，就按功能（电源、MCU、接口、模拟等）把设计划分为真实的子图，并为每张子图给出明确的接口：在子图内部使用 `hierarchical_label`，在父图符号上使用同名且方向匹配的 `pin`，并用 `validate_sheet_pins` 与原生网表核对。全局标签是例外，不是图省事的工具——仅允许用于真正全板通用的网络（例如未画成电源符号的单一辅助电源轨），且每一个都要列入项目 `composition.labels.allow_global_labels`。电源轨只使用原生电源符号——在电源或地网络上使用全局、层次或局部标签属于 G1 阻断缺陷，不是风格选择。

一张图可以包含多个原型；应划分区域，而不是强加统一的「POWER 页」全局模式。

## 6. 确定性的冲突消解

按此顺序处理：**(1)** 保住 L0；**(2)** 重新定位外围器件；**(3)** 合法的旋转/镜像；**(4)** 仅使用已批准的替代符号或多 unit 表现形式，绝不改动引脚编号/网络身份；**(5)** 短正交导线；**(6)** 边界标签，优先局部 → 层次+图纸引脚，仅在正当理由时使用全局；**(7)** 增大间距；**(8)** 调整或拆分图纸。

对于「直连导线与交叉」之争，先移动对象再引入标签。对于「少标签与长导线」之争，优先准确的标签。对于「全局标签与层次端口」之争，除非网络真正全板通用，否则选层次端口。对于「一页拥挤与层次化」之争，只要存在不止一个功能模块就拆分为真实的子图。对于「居中与信号流向」之争，保持流向并整体平移图形。对于「地朝下与过多折弯」之争，考虑合法的符号旋转。对于「标签朝向与锚定」之争，保住电气锚点并调整文字。**不要**通过盲目拉长导线来解决布局冲突。

## 7. L4 在不改变电路的前提下优化

采用字典序优先级：先达成 L0–L3 可行；然后优化可读长度、非法交叉、折弯数、冗余标签、对齐、均衡与可用面积。阈值/权重存放在项目策略中，而不是全局魔法常量。不同页面角色可能需要明确的例外；如果「最少标签」与「最短导线」相互冲突，它们就不是等权目标。

## 8. L5 证据矩阵与实现诚实度

| 检查项 | 证据 | 当前实现边界 |
|---|---|---|
| 组件集合、取值/封装、引脚-网络映射、NC/DNP 与单引脚网络 | 独立指定的期望图与 KiCad 原生网表比对，加上 XML 未导出的源属性 | 部分 `schematic_candidate.py` 与原生命令；NC/DNP 需单独检查 |
| ERC | 实际的原生 ERC 报告及豁免项处置 | 已有支持路径；ERC 本身不能证明电气应用正确性 |
| 图纸/层次/边框与引脚范围 | `schematic_style.py`、系统接口引脚端点 | 有限的静态筛查 |
| 引脚外向向量、本体穿越、标签变换与实际锚点 | 符号实例几何与变换后的引脚 | **几何自动检查器尚未完全实现**；每张图都需人工审查 |
| 全部文本碰撞、组合包围盒与页面边缘 | 实际字体/渲染几何加精确规则计算 | **尚未完全实现**；需要 PDF/SVG 视觉审查 |
| 串并联角色、反馈、长导线与交叉 | 明确的功能块与拓扑审查 | AI 加工程师审查，并有独立的实际网表 |
| 整页与约 200% 局部视图 | 带图纸与对象位置的实际 KiCad 导出/GUI 视图 | AI/工程师验收；不允许自我签认 |

自动检查器只可对**其实际测量的部分**宣告 PASS。无支撑的强制检查应标为 `UNAVAILABLE` 并附人工证据；如果项目明确要求全自动门禁，缺少实现即意味着 **BLOCKED**。每条违例都应包含图纸/对象、网络、严重度、来源规则、复现方式、修改前后哈希与复测。不能因为脚本返回零就绕过硬性几何违例。

独立的原型测试与三遍绘制证据见[跨原型验证](schematic-cross-archetype.md)。prototype_validation 记录是「测过什么」的证据，而不是「已实现通用几何引擎」的证据。

## 9. 执行、回退与完成

```text
Manufacturer data + independent expected topology + system interface contract
  → function graph / page archetypes
  → series/parallel/feedback roles and cross-block ports
  → exact symbol pin transforms and outward vectors
  → relative anchors and grid coordinates
  → short local wires + legal labels/hierarchy
  → independent visible text layout + combined-bounds centering
  → native export + expected-netlist equivalence + ERC
  → bounded geometry screening + full-page and ~200% view
  → sourced AI review + actual engineer approval
```

已确认的 L0/L1 硬性违例会阻断当前候选；就地修复并重跑原生检查。任何网络变更都回到 L0 验证。软目标只产生改进建议，而不是虚构的电气失效。反复的布局失败应当促成页面拆分或明确的工程审查，而不是无限重试循环。

完成要求：独立建立的拓扑与原生导出一致、所有相关 ERC 发现都有处置、实际可用的硬性检查已执行、无支撑的几何项完成全面视觉审查、记录 AI 发现的问题，并由工程师批准**当前**版本。这不能替代厂商的应用验证或真实硬件性能。

## 10. 集成与对抗性测试要求

新的原理图绘制、重排与静态视觉审查均须遵循本规范。既有的 `schematic_style.py` 与 `schematic_candidate.py` 不会因为本文档存在而获得新能力。新的几何引擎需要覆盖以下内容的正反例夹具：符号内部短路、镜像标签锚点、穿过本体的导线、长距离跨块连接、位号/值重叠、侵入标题栏、虚假串并联表现、绘图偏离中心、以及编辑后的网表变化。还要包含合法的反例以避免误报。

## 可执行的 R10 构图扩展

[专业原理图构图检查](schematic-composition-gates.md)实现了有证据约束的标题栏/注释碰撞筛查、原生电源符号策略与只读的页面规划/拆分筛查。在新项目上使用它们，同时保持既有的 L0–L5 优先级。这些检查需要经验证的渲染边界清单，并且**不**实现完整的自主 KiCad 符号放置、导线布线、图框几何提取器或自动化文本碰撞求解器。无法获得的测量必须保持未批准状态。
