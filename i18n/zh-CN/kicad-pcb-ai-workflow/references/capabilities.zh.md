# 能力矩阵与工程局限（R10）

## 已实现且有边界的能力

- 由清单绑定的 `workflow.py` 前端分发任务专属的 Python 脚本，包含模块级参考资料加载与各自独立的不可变 G1–G4 证据。
- `device_knowledge.py` 支持官方来源摄取、卡片校验、确切 MPN 的缓存优先解析、验证/新鲜度检查、项目冻结资料包与阶段专属简报。
- G1：当前原理图证据准备与 AI/工程师审查；G2：实际符号/封装锁定与器件卡片映射；G3：当前板子放置评估；G4：已保存板子的铺铜/静态审查与证据关卡。
- Python 提供选定的高速/PI 确定性检查、设计意图审计、来源/网络一致性、离线布线搜索与制造预检。每项都有声明的适用范围，且不会自动修改 PCB。
- Konnect MCP 的动态发现与限定范围的夹具验收允许**特定**的真实操作。已验收的能力必须匹配可执行文件/构建、KiCad 版本、工具 schema 以及经过测试的对象/几何参数。
- 工作区索引、不可变检查点与有界的报告摘要减少了重复项目与不必要的 AI 上下文摄取；若没有单独的已验收操作，它们都不会改动 KiCad 的设计数据库。

## 不会自动被证明的内容

本 Skill 不提供通用原理图生成器、通用自动布线器、自动放置器、有保证的 3D 碰撞/热/SI/EMC 求解器或自动工厂批准。干净的 ERC/DRC、一次模拟的 A* 布线、一条画出的禁布区、一张缓存的器件卡片或一个程序化组装的 Gerber 归档，都不能证明产品适用性。复杂的多板/层次、RF/高速与生产场景需要适当的真实器件/厂商/工厂与工程证据。

## 版本策略

KiCad 10.0.7 是历史推荐版本，不是版本上限。稳定的 KiCad 10.x 在通过对应的实际原生测试后可以考虑；KiCad 11+ 应以仅 CLI 的范围与单独验证过的 Konnect/IPC 能力来评估，而不是笼统假设与 `pcbnew` SWIG 兼容。KiCad 9 与 RC/nightly 需要单独验证。历史上的 KiCad 10.0.8 集成证据或 R10 软件单元测试**不构成**对新安装 Konnect 二进制、任意板子或制造发布的全面验收。

独立设计审查、制造数据与实际硬件测试仍然必需。参见 [最新工作流](latest-complete-workflow.md)、[Konnect 验收](konnect-capability-migration.md) 与 [工程规则](engineering-rules.md)。
