# 项目库资源与文件完整性

在适用时，优先使用经过验证的官方 KiCad 符号和封装。对于外部器件，在用于项目之前，应核实其真实来源/许可证、制造商推荐的焊盘图形、准确的 MPN/封装、版本及适用范围。应将准确的符号/封装文件及 3D 模型保存在已知且可安全解析的项目路径下；避免运行元件库附带的外部脚本或未知 shell 命令。

资源锁应通过 SHA-256 绑定每个经批准的库文件及相关项目相对路径。`resource_guard.py lock` 会创建新的显式锁；`check` 会校验当前文件，并可通过 `--review-config` 使用 G2 项目源卡。任何缺失、符号链接越界或已更改的文件都会阻止依赖它的审查。引脚到焊盘的电气正确性、EP、极性、NC 引脚以及实际装配变体，仍需单独依据制造商来源并由工程师验证。

将原理图同步到 PCB 时，应保留 UUID、物理焊盘网络映射、受保护的布局以及原生设计规则。资源哈希一致不能绕过 G1/G2、实际网表一致性、原生 ERC/DRC 或最终制造签核。参见 [G2 模块](module-resources.md)和[器件来源](device-knowledge.md)。
