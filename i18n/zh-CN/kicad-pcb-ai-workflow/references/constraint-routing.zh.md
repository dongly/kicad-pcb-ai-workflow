# 脚本规划布线：请求契约、后端验收与安全回退

## 规划与执行的区别

`routing_policy.py` 负责校验并结构化布线请求与后端选择，它不会自动铺设最终的 KiCad 铜层。`script_route_search.py` 提供的是有界离线网格/A* 路径*提案*，而不是经过制造认可的走线。外部布线的 Freerouting SES 在成功导入、保存、重载并通过原生验证之前，同样只是一个候选结果。

## 必需的请求输入

必须指明当前项目/板卡的身份与源哈希；板厂认可的层序、铜厚以及走线/间距/过孔限制；允许的网络层与 NetClass 分配；受保护的元件、对象、既有走线、keepout 与板边；网络优先级与端点；已验收的后端标识；工程师提供的差分、时序、RF、电源与回流路径约束；以及操作预算。未知网络、未知源规则与不受支持的几何约束不得默认按安全的普通布线处理。

执行必须限定在已授权的独立候选项目或明确授权的工作项目内，并遵守单一 Konnect MCP 写入方。记录命令/规划修订版本、对象标识、源/目标几何信息，以及该操作能否被安全撤销。新的外部版本、变更的 schema 或更广的网络/几何范围都需要新的相应能力证据。

## 失败与受控恢复

每个有界布线批次之后都要回读；遇到超时或结果未知时，**不要**重放同一个非幂等操作。如果规则、受保护对象、设计意图或网络身份出现冲突，立即停止。不要禁用 DRC、放宽制造商公差、移除必需网络，或悄悄切换到未经验证的原生脚本作为回退。使用受支持的 Freerouting 适配器时，应把 DSN→SES→导入→原生保存/DRC 视为各自独立的验收步骤。

中间布线可以报告经明确批准的未完成连接；G4 之前的最终布线必须解决所有*必需*的未连接项及适用的阻塞项。始终验证实际保存的铜层几何、填充、过孔过渡、间距、回流/参考平面以及完整的原生 DRC。参见 [PCB 模块](module-pcb.md)与[工作流节点 10](latest-complete-workflow.md)。

## 精确的请求与源绑定契约

使用 `assets/routing-request.template.json`（schema 版本 1）。必需的请求字段包括 `request_id`、`strategy=script_planned`、`phase=incremental|final`、明确的 `runtime`（`platform`、KiCad 与 API 版本）、经过哈希的项目相对 `inputs`、逐网络工程约束、稳定的待处理连接 ID 以及有界的资源预算。示例中的 `null`/占位符不满足契约。每个输入都必须通过 `file/sha256` 绑定板卡、实际 XML 网表、叠层、原生规则与受保护对象文件，且不得跟随逃逸出项目目录的符号链接。哈希漂移是**阻塞项**，而不是变相允许悄悄刷新哈希。

每个目标网络都需要有记录的类别、制造商/项目来源定位符，以及有界的允许层、线宽、铜层间距、板边/keepout 间距、过孔与回流要求。须区分：持续电压/电流、大电流与热、时钟/复位、差分/高速、RF/模拟/Kelvin、普通、地，以及明确的仅手动类别。未知网络不得被悄悄降级为普通信号。`parameters` 必须是带单位与适用范围的明确有限数值工程值。差分/RF/时序/电源类别需要其对应的附加约束；这个策略解析器不是阻抗求解器，也不是 SI/PI 求解器。

`pending_connections` 是绑定到实际原理图 XML 中明确 `(ref,pin)` 端点的稳定 ID；`target_connection_ids` 声明本批次。预检检查的是声明的端点与网络划分，而不是实际已存在的铜层连续性或待处理列表的完整性。`budgets` 必须限定时间、迭代次数、最大过孔数与随机种子。可以允许零过孔；如果允许过孔，则须逐网络指明实际过孔几何与孔间距。执行后端必须强制执行预算，而不是仅在规划中原样回显。

在一个经过哈希的层文件中声明实际的铜层顺序与角色。只有 `signal` 或明确许可的 `mixed` 铜层支持信号布线；`reference_plane` 与 `power_plane` 保持受保护状态，除非有正当理由的项目专用规则明确允许不同设置。`allowed_signal_layers` 不得引用不存在/被禁止的层。对于四层及以上铜层，要求提供真实的板厂叠层并进行相邻参考/回流审查；仅凭层名或名义叠层数无法确立特性阻抗。

受保护对象契约示例：

```json
{"schema_version":1,"locked_policy":"preserve_all","object_uuids":[],"plane_layers":["B.Cu"],"nets":["GND"]}
```

既有的锁定封装与铜层天然受保护。只有被明确标识、事先审查过的 `reroutable_uuids`（合格的 segment/arc/via 对象）才可以修改。它们不得包含锁定对象、被排除的网络、平面层或非布线几何。每一次实际编辑增量都必须与保护集合对账。

## 后端注册与验收

`routing_policy.py` 支持*仅规划*的后端类型 `native_script|freerouting`；这是一份**历史性的后端验收契约**，并不是对第二个活跃 KiCad 写入方的授权。在 R10 下，最终的真正 KiCad 写入仍要通过受支持的 Konnect MCP 工具完成，并接受其独立的按构建/schema/范围验收。绝不盲目地对活跃 GUI 项目执行离线布线器的脚本。

后端记录绑定 `id`、`kind`、版本、工件 SHA 与验收 SHA。验收必须指明 `record_type=routing_backend_acceptance`、`decision=accepted`、`scope=kicad_end_to_end`、检查日期与到期日期、实际的审查者/理由、精确的运行时平台/KiCad/API 版本、受支持的约束、几何/能力，以及针对 `native_drc`、`netlist_parity`、`save_reload`、`protected_object_diff`、`rule_hits`、`connectivity` 的独立证据。仅仅产出 DSN 或 SES、在 JSON 中放置 `passed=true`，或运行合成测试夹具，都不构成制造/物理资格认定。如果所需的精确能力缺少当前有效的验收，应选择 `PENDING_BACKEND_ACCEPTANCE`，而不是编造一个执行它的规划。

**现行 R10 七阶段策略取代旧的“原生脚本优先”表述：**在实际的关键网络布线/保护完成之后，将经过验证的 Freerouting 2.5.0 用作**合格普通网络的离线候选生成器**，并排除 GND 与关键类别。`routing_policy.py` 的后端验收契约本身只授权一个合格的 `konnect_mcp` *活跃 EDA 写入方*；遗留的 `native_script` 与 `freerouting` 后端类型都不是活跃写入方。`freerouting_adapter.py` 负责有界的 DSN→SES 暂存（staging），`routing_seven_stage.py` 增加只读的规划/导入/最终几何检查。两者都无法在没有独立证据的情况下证明原生 SES 导入、规则保真度、层映射、覆铜填充、保存/重载或 DRC。缺失原生能力时必须 BLOCK，而不是悄悄切换到未经验证的写入方。

| 规划状态 | 含义 |
|---|---|
| `PREFLIGHT_READY_NOT_EXECUTED` | 输入、声明的策略与验收记录均合格，**未写入任何铜层** |
| `PLAN_READY_NOT_EXECUTED` | 已产出有界的规划信息，**未写入任何铜层** |
| `PENDING_BACKEND_ACCEPTANCE` | 后端证据缺失/过期/不足；尚未可执行 |
| `BLOCKED` | 源/规则缺失、哈希变更、不受支持的功能、受保护对象冲突或请求格式错误 |

用法：

```bash
python scripts/routing_policy.py preflight /project --request routing-request.json
python scripts/routing_policy.py plan /project --request routing-request.json --output-dir /project/03_REPORTS/route-plan-r1
python scripts/routing_policy.py plan /project --request routing-request.json --after-attempt failed-attempt.json
```

### 失败处理与回退

只有真实的、与源绑定的 `NO_ROUTE_WITHIN_BUDGET` 才可以触发针对另一个**同等已验收**后端的规划。它必须携带 `schema_version=1`、当前请求 SHA、初始板卡 SHA、失败后端 ID、真实日志证据哈希，以及非空的剩余连接 ID 列表。违反规则、移动受保护对象、丢失源身份或缺少受支持能力的尝试，在未重新批准的情况下不能通过更换后端或加大约束来挽救。预算耗尽并不能证明连接不可行。

回退从原始检查点重新规划；不要复用失败执行中未经验证的部分铜层。若要保留已完成的线段，应独立验证并保存该部分候选结果，然后创建一个**新的**请求，锚定到其实际的板卡、网表、保护与规则哈希。对于中间布线，只显式跟踪已批准的剩余连接 ID；不要豁免整个 DRC 类别。对于最终布线，在最终填充之后独立重扫*所有*必需连接，包括地网络。一份全绿的规划绝不意味着板卡已布线完成；连接性、DRC、引脚到焊盘一致性、受保护对象完整性、叠层/回流路径以及项目专属的时序/SI/PI 仍需单独验证。G1–G4 与 `EXPORTED_NOT_RELEASED` 不受影响。

## 电源走线：查表主干线宽、+0.254 mm 与受控焊盘引出

**现行 R10 软件防护：**`routing_policy.py` 现在要求对完整的具名 XML 网络清单进行分类，拒绝把被归类为 `GND` 或 `REFERENCE_PLANE` 的目标交给普通布线器，并按用户提供的 1/1.5/2 oz 电流表**外加 0.254 mm 最小附加铜宽**来设定声明的**电源干线** `track_width`，然后与已批准的温升与压降线宽下限进行比较。该表格是**未指明温升、内外层位置与来源出处的经验数据**；它不能证明符合 IPC-2152 载流能力。表中缺失的铜厚（例如 0.5 oz 内层铜）、过大的电流，或缺失热/压降证据都会**阻塞**，而不是外推出一个虚假的安全线宽。选择实际可用的 KiCad 布线线宽时应**向上取整**，而不是向下。线宽余量不是间距。

**重要例外：细间距电源焊盘不是宽干线。**范围收得很窄、长度很短的**焊盘引出/颈缩（pad-escape/neckdown）**可以把小焊盘连接到更宽的干线；干线的 +0.254 mm 余量不得被强加为**全局 Board Setup 最小走线宽度**，也不得作为无条件的逐线段绝对最小值。全局 Board Setup 最小值仍然是经过验证的板厂绝对制造下限；KiCad netclass/自定义规则应在范围紧收的焊盘引出之外维持宽干线。**不得进行一刀切的规则放宽：**颈缩只允许针对其具名网络、确切的 `reference/pad`、层、有源可查的区域与长度来批准。仅凭整个封装范围的 courtyard 可能过于宽松；应使用经独立验证的最小范围规则区域。KiCad 官方自定义规则示例支持用 `intersectsCourtyard` 实现局部 `track_width`，但在使用前必须回读实际的规则优先级/生效范围，并用一个故意失败的测试夹具加以测试。

**必需的颈缩提案契约（尚未自动强制执行）：**确切的 `net`、`ref`、`pad`，已批准的 `layer`，实际焊盘与相邻焊盘的铜层几何，`escape_width_mm`，有源可查的 `max_escape_length_mm`，允许的例外数量，区域多边形/UUID，干线 `main_width_mm`，该分支承载的设计电流，铜厚，经估算/审查的压降与温升，参考平面/回流要求，已批准的原生规则范围，以及权威来源/证据哈希。线宽不得低于实际制造下限，不得侵犯相邻焊盘间距，也不得超出局部热/电流/压降限值；短引出**并不自动满足载流安全**。必要时考虑并行电源引脚、多个缝合过孔或覆铜区，并验证连接器/焊盘/过孔的额定值。如果缺少任何必需证据，使用 `NEEDS_NECKDOWN_ENGINEERING_REVIEW` / `BLOCKED`，而不是发明一个默认值。

**执行目标：**解析实际封装焊盘/相邻焊盘 → 计算可行的引出线宽与最短合法引出路径 → 绑定确切的有源可查局部原生规则 → 预留引出区域 → 创建短窄线段，一旦合法立即加宽（可在焊盘/走线/走线之间选用经验证的泪滴） → Konnect 保存并独立回读实际对象 UUID/线宽/长度/间距 → 把实际线宽例外限定在其已批准区域内 → 完成布线/覆铜填充 → 完整 G4 原生 KiCad DRC、连接性与电气/热审查。生效的最小间距/线宽规则不得被覆写至低于 KiCad 的全局制造下限。KiCad 泪滴改善过渡几何；**它们并不能确立窄线段的热安全**。

现行通用 `script_route_search.py` 对每条简单普通连接**只用一种线宽**，没有混合线宽的焊盘引出求解器、自动的原生逐线段 DRC 规则应用，也没有验收回执。不要因为上述契约已有文档就**声称**它目前能执行电源颈缩布线。对于默认线宽较宽的信号类别，同样的短引出几何原则可能适用；对于差分、时钟或 RF，须独立验证不连续性、对称性、阻抗与时序，绝不悄悄改变线宽。

**回退：**优先使用受支持/当前版本且已验收的 Konnect 交互式或专用布线操作，并回读保存状态。有界 A* 预算失败可以在相同的已批准约束上重试；外部生成的 Freerouting SES 在被独立导入受保护的 KiCad 候选并验证之前只是*候选*。如果两种工具都无法保留范围化规则/几何，则停止并要求慎重进行工程/手动布线，绝不自动豁免安全约束。

## R10 分阶段 Freerouting 优先候选

对于普通网络批次，推荐的工程方向是外部布线的 **Freerouting DSN/SES 候选**，而不是一个新的由 LLM 掌控的多网络 A* 生产布线器。在适配器、原生导入与规则保真度验收通过之前，这**不作为生产默认启用**。v2.5.0 适配器现已支持经审查的 DSN 哈希、明确批准的 `.rules` 哈希，以及通过 `-inc` 进行的类别排除；它仍然无法证明源 NetClass 成员关系或已导入的铜层。关键电源、受控阻抗、差分、RF、Kelvin 与 GND 回流几何仍由经过独立验证的 KiCad/Konnect 关键布线与验证负责。不允许削弱 0.254 mm 电源干线余量、范围化的焊盘引出、H/V/45 预期、对象保护或 G4 闸门。参见 [完整的 Freerouting 优先候选契约](freerouting-primary-routing.md)。
